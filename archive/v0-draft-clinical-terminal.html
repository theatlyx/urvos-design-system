A design system for Urvos

Color is earned, not decorative.

Everything below is monochrome by default. The only color that appears is color that means something clinically — a critical allergy, a caution flag, an AI-assisted suggestion. That restraint is what makes the signals trustworthy at a glance, across a 12-hour shift, on the smallest tablet at bedside.

06 · Likely Gaps

What the brief doesn't mention yet

Beyond the components above, these are the things that tend to surface late in EMR builds — after the first real pilot, not before. Worth locking into the same foundation doc now.

01
Offline / degraded-connectivity states

Wards with poor connectivity need an explicit "unsynced" indicator on every chart edit, distinct from a normal saved state.

02
Consent & e-signature capture

A dedicated pattern for ABDM consent artefacts and physician sign-off — different from a generic "confirm" button, needs its own audit trail visual.

03
Skeleton / loading states for FHIR calls

Medplum/CARE round-trips aren't instant — every data table and banner needs a defined loading skeleton, not a blank flash.

04
Empty states

"No allergies recorded" must look deliberately different from "still loading" — an empty chart section is a safety-relevant distinction, not a cosmetic one.

05
Print / PDF stylesheet

Discharge summaries, prescriptions, and lab reports need a print-specific layout — the dark patient bar and sidebar chrome should never print.

06
Large touch targets for gloved use

Bedside tablet interactions (vitals entry, medication administration/barcode scan) need a distinct "clinical touch" density mode with bigger hit areas than desktop.

07
Barcode / QR scan feedback

Medication administration (5 Rights check) needs a dedicated scan-confirmation pattern — success/mismatch states, not a generic toast.

08
Audit trail / "who changed this" indicator

Given the HIPAA audit logging requirement, any edited clinical value should support a small inline "history" affordance, not just a separate audit log screen.

09
Multilingual / regional numeral formats

ABDM context implies Hindi/regional-language support and Indian date (DD-MM-YYYY) and currency conventions as first-class, not an afterthought locale switch.

10
Dark mode for night shift

The token set above is light-first; a true dark variant (not just inverted grays) matters for ICU/night shift use and deserves its own contrast pass, not an automatic invert.

11
Keyboard-first power workflows

Physicians charting dozens of patients a day need documented keyboard shortcuts and focus order — a mouse-only spec will get rejected in review.

12
Multi-tenant white-label tokens

Since Urvos is multitenant, the token file should separate "system tokens" (signal colors, spacing — fixed) from "tenant tokens" (logo, one accent) so hospitals can brand without breaking clinical-safety colors.
